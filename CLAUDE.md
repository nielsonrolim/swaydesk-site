# CLAUDE.md

The website of Swaydesk, a desktop on top of Sway: <https://swaydesk.nielsonrolim.com>. Static site built with
Hugo 0.147, its own templates (no theme), published on GitHub Pages. Three languages, all first-class: Brazilian
Portuguese (`pt-BR`, the default), American English (`en-US`) and Latin American Spanish (`es`, `es-419` in
`lang`/`hreflang`), served at `/pt-br/`, `/en-us/` and `/es/`. The root sends `pt*` browsers to Portuguese, `es*`
to Spanish and the rest to English (`static/js/lang.js`). The site makes no
requests to other hosts: no CDN, no web fonts from outside, no analytics, no cookies.

## Layout

- `content/pt-BR/`, `content/en-US/`, `content/es/`: the pages, one Markdown file per page, with the same file
  names in all three. `guide/` holds the user guide.
- `data/isos.toml`: the Download page's ISO cards (Release tag, file, size, SHA-256, Secure Boot, `published`).
  Its header comment explains each field.
- `data/shortcuts.json`: generated by `scripts/shortcuts.py` (see its docstring); don't edit it by hand.
- `data/demo.toml`: the demo video and its chapters, per language (`es` reuses the English video, chapters in Spanish); `home = true`
  marks the chapters the home page's panel shows.
- The home page (`layouts/home.html`) follows the design mockup: its texts are in the front matter of each
  language's `_index.md` (`hero`, `facts`, `demo`, `components`, `shortcuts`, `install`), the packages' version comes from
  `data/isos.toml` (`packages`, required: the build fails without it; `tag` is the ISOs' Release), the profiles from `data/shortcuts.json`, the component icons from `_partials/icon.html`.
- `layouts/`: page templates, `_partials/` and `_shortcodes/` (`iso`, `distro`, `step`, `components`…).
- **Components:** `data/components.toml` (its header documents the fields) drives the list on `/components/` (shortcode
  `components`) and one page per component with `page = true`, made by `content/<lang>/components/_content.gotmpl` (the
  same file in the three languages) and drawn by `layouts/components/page.html`. A new component is one
  `[[components]]` with its three languages; `package`, `start` (or the per-language `start_text`, when nothing goes in the Sway config) and `waybar` stay empty until known, and the page says
  "being written".
  `_partials/topbar.html` (logo, menu, languages, Download button, theme), `nav.html` (the top menu: every
  `main` menu entry but home and Download), `locale.html`, `theme-toggle.html` and `footer.html` are on every
  page. Below 1000px the top bar stays on one line: the menu, the languages and the theme button move into a
  `<details class="menu">` (`./menu`), and the page crumb is hidden.
- `i18n/pt-br.toml`, `i18n/en-us.toml`, `i18n/es.toml`: interface strings used by the templates, with the same keys.
- `assets/`: CSS and images processed by Hugo. `static/`: fonts, scripts, video, `404.html` and `CNAME`.
  The logo is `static/images/icon.svg` (dark) and `icon-light.svg` (light); the CSS shows the one for the theme.
  The colors are tokens on `:root` in `assets/css/site.css`, with the dark set under `[data-theme="dark"]` and
  `prefers-color-scheme`; the values follow the design mockups (the accent is `#45abb7` on dark, `#2e8792` on light).
- `hugo.toml`: site config, menus per language, `params.code_repo` (the public code repository whose Releases
  hold the ISOs).

## Build and check

Run both before every push; CI runs the same and a failure blocks the deploy:

```sh
docker run --rm -u "$(id -u):$(id -g)" -v "$PWD:/src" -w /src ghcr.io/gohugoio/hugo:v0.147.0 build --minify --panicOnWarning
python3 -I scripts/check-links.py public
python3 -I scripts/check-layout.py public
python3 -I -m unittest discover -s scripts -p 'test_*.py'
```

- `--panicOnWarning` turns any Hugo warning (a missing page, a bad shortcode) into a failure.
- `check-links.py` checks that every root-relative `href`/`src` (starting with `/`) in `public/` points to a
  file that exists, that every `#anchor` on a page link is an id on that page, and that a page links only to its
  own language (the switcher's links, with `hreflang`, are the exception). Relative and external links aren't
  checked: open those by hand when you change them. A missing or empty `public/` fails it (a failed build).
- `check-layout.py` opens Install and three component pages (dock, greeter, screenshot) in the three languages
  in a headless Chrome at 1200 and 390 px, clicks every distro tab, and fails when a panel opens at a different
  distance from the tabs than the first one, or a copy button (in any panel) isn't as tall as its code field; a page
  where it finds fewer than two tabs or no copy block fails too, so a renamed class can't pass. It serves a copy of
  `public/` on 127.0.0.1 and runs Chrome with a temporary HOME and no session bus. Its tests skip without Chrome,
  except on CI.
- `check-components.py` checks `data/components.toml` against what the templates expect (its docstring lists
  the rules: known group and icon, unique id, the three languages with a name and a text, the shot exists,
  `waybar` only on the bar as `swaydesk-<name>`, `unit` only with a snippet include, no page fields on a card
  without a page). CI runs it through the unittest step (`test_the_real_data_passes`).
- `check-packages.py <swaydesk checkout>` checks that every `package` in `data/components.toml` is a `Package:`
  of the checkout's `debian/control` and a name in its `packaging/arch/PKGBUILD` `pkgname=(…)`, so no page
  prints an install line for a package that doesn't exist. CI doesn't run it (it needs that checkout): run it
  against a clone of github.com/nielsonrolim/swaydesk at the release whenever a `package` changes.
- **Both Hugo 0.147 and the newest build the site.** CI publishes with 0.147, which lacks what 0.156+ replaced, so
  the templates never call a deprecated API directly: `partialCached "data.html" .` instead of `site.Data`,
  `partialCached "sites.html" .` instead of `site.Languages`, `site.Params.locale` (`[languages.X.params]` in
  `hugo.toml`) instead of `languageCode`, and `layouts/sitemap.xml` for the sitemap's hreflang. Aliases are
  relative to the page's folder (`apps/`): newer Hugo prefixes an absolute one with the language. The uppercase
  `/pt-BR/` and `/en-US/` redirects are static files (`static/*/index.html`).
- `hugo server` (Hugo installed locally) previews at <http://localhost:1313>.
- `public/` and `resources/` are build output and are not committed.

## Rules

- **All three languages change together.** Any page, data or `i18n` change lands in `pt-BR`, `en-US` and `es`
  in the same commit, with the same meaning; every new page ships in all three. Internal links use the lowercase
  language prefix of their own language (`/en-us/...`, `/pt-br/...`, `/es/...`); a renamed heading changes its
  anchor, so update the links to it.
- **Spanish is neutral Latin American**, with "tú", and names the interface as the app does: the `msgstr` of the
  code repository's `po/es.po` (e.g. "Tema del escritorio", "cuadrícula de aplicaciones").
- **ISO data must match the Release.** In `data/isos.toml`, `tag`, `file`, `size` and `sha256` come from the
  GitHub Release of `params.code_repo` and its `SHA256SUMS` file. Copy the hashes from that file, never from
  elsewhere. Size is in decimal GB, rounded to one place. Set `published = false` for an ISO that isn't
  in the Release. When an ISO in the Release is replaced, update its `sha256` (and `size`).
- **Versions are consistent.** The version on the Download and Install pages, the Release links and
  `isos.toml`'s `tag` name the same release.
- **Links are checked.** Run `check-links.py` on every change, and open any external link you add.
- **Independent of Sway.** Every page's footer (`i18n` key `independent`), `static/404.html` and the home intro say
  that Swaydesk is not affiliated with, or endorsed by, the Sway project. Keep them, and don't use Sway's logo or
  wording that suggests an official Sway project.
- **No outside requests.** Don't add CDNs, remote fonts, trackers or embeds; put assets in `static/` or `assets/`.
- **Keep this file current.** A change to the layout, the build or check commands, or these rules updates
  `CLAUDE.md` in the same pull request.

## Deploy

`.github/workflows/pages.yml` builds and publishes on every push to `main` (and on manual dispatch): Hugo
0.147.0 checked by SHA-256, the scripts' tests, `hugo build --minify --panicOnWarning`, `check-links.py`, `check-layout.py`, then GitHub
Pages. `hugo-latest.yml` builds the same with the newest Hugo release on every pull request, push and weekly; it
never publishes and its failure blocks nothing, but a red run there means the next Hugo bump needs work.
Actions are pinned by commit. Changes go through a pull request; after the merge, check the live pages in
all three languages. History on `main` is never rewritten (no force-push).
